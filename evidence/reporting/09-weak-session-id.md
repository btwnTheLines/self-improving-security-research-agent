# Report 09 — Weak (predictable) session identifier generation

## Summary
A session identifier generated by the application is a trivially predictable, incrementing integer, defeating the purpose of a session token.

## Confirmation status
**Confirmed vulnerability** (token predictability observed directly).

## Affected component
Authenticated "Weak Session IDs" exercise (`/vulnerabilities/weak_id/`), Generate action that sets a `dvwaSession` cookie.

## Preconditions
Authenticated session.

## Steps to reproduce
1. `POST /vulnerabilities/weak_id/` (Generate) three times, observing the `Set-Cookie` header each time.

## Expected behavior
A session/token value should be unpredictable (cryptographically random) and not enumerable.

## Actual behavior
Three consecutive Generates returned:
- `Set-Cookie: dvwaSession=1`
- `Set-Cookie: dvwaSession=2`
- `Set-Cookie: dvwaSession=3`
The token is a plain sequence.

## Security impact
Predictable session/state tokens allow an attacker to guess/replay another party's session value and to detect active sessions, enabling session-based attacks. Impact supported (with the caveat below): predictable generated token.

## Evidence / PoC
`Set-Cookie: dvwaSession=1`, then `=2`, then `=3` (raw: `evidence/reporting/raw/weak1.txt`, `weak2.txt`, `weak3.txt`).

## Remediation
Generate session/state tokens from a cryptographically secure random source with sufficient entropy; never use an incrementing integer or other guessable sequence.

## Severity rationale
The app-generated `dvwaSession` token is clearly predictable (Low/Medium as reported). Reported Low because the primary authentication cookie (`PHPSESSID`) was not shown to use this weak generator.

## Limitations / remaining uncertainty
The demonstrated predictable token is application-generated (`dvwaSession`). Whether the primary login `PHPSESSID` derives from this weak generator was **not** established; that predictability is not claimed.
